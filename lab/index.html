01 / COMPILERSC++20

TensorForge

How does one tensor graph become checked CPU code and custom CUDA work?

Typed graph → gradients → C++ / Triton → owned outputs
Show me a result
Generated gradients train y = 2x + 1: MSE 11 → 3.55e-15 after 100 checked updates. The video introduces graph optimization first.
The hard part
Custom kernels must preserve the reference shapes, NaN/zero rules and generated gradients.
Evidence to inspect
173 generated C++ graphs pass 46,885 comparisons without runtime opcode dispatch. Native CPU/CUDA and the Triton bridge pass the same 106 graphs and training. On T4, 595 graph nodes use custom kernels and 780 use the library; block boundaries add 354,570 comparisons and 27 invalid-bundle refusals.
Run it ↗Inspect the generated C++ ↗Inspect native Triton ↗
Tradeoff and next boundary

Five elementwise operators use trusted Triton cubins; reductions and matmul use ATen. Broadcast materialization and context synchronization prioritize correctness. Native Triton activity is separately profiled on T4. Per-call planned CPU/CUDA storage passes the same suite and distinct-input concurrency tests. A checked graph uses 48 instead of 80 logical payload bytes. ATen temporaries, persistent public device buffers, more dtypes and hardware counters remain open. Host/device copies are included; no GPU speedup is claimed.

02 / SCHEDULINGPython

InferMesh

How can three clients share batched model workers without stealing each other’s budget or output?

Tenant queues → fair batches → supervised CPU replicas
Show me a result
Two real CPU-model workers serve 24 requests in six four-row calls, checked against single-prompt greedy generation. One caller expires while its three batch peers finish without a child restart. The separate SSE adapter delivers text incrementally.
The hard part
An expired row keeps its output position and quota until the shared batch physically retires.
Evidence to inspect
122 core, 45 tracing, 13 HTTP and five HTTP/tracing tests. Three rejected mutants check compatibility, quota ownership and shared deadlines. A reproduced double-cancellation quota leak is fixed. Real-model tests keep mixed budgets separate and verify child cleanup; this is not a production SLO.
Run it ↗Inspect fair CPU batches ↗
Tradeoff and next boundary

Batching preserves round-robin selection and matching token budgets, not FIFO completion. Each caller keeps its deadline; physical work may continue for its peers, retaining quota. Single-request child preemption and real SSE have separate contracts. Multi-host routing, shared state and production SLOs remain open.

03 / DURABILITYC++20 / POSIX

NanoExchange

How can matching and recovery preserve the same market state after a lost acknowledgement?

Canonical command → fsync → risk / match → receipt
Show me a result
Total-store admission handles 201 commands with a 1,326-byte staged peak under a 4,096-byte logical cap. At full capacity, a new command fails while its historical receipt still works.
The hard part
Persist request identity so a retry after an uncertain acknowledgement cannot execute twice.
Evidence to inspect
1,852 Linux fault scenarios cover 14 direct call families and recovery from a full WAL, state image or compacted base. They caught interrupted one-byte reads and an ignored metadata error, alongside ambiguous rename. Recovery preserves returned receipts; read-only reopening leaves original files unchanged.
Run it ↗Inspect the failure and fix ↗
Tradeoff and next boundary

Typed state and explicit compaction preserve FIFO, counters and current receipts. Compaction discards original command history; bounded epochs reject expired identities. Whole-book response previews and per-command directory scans have a cost. Process-kill tests do not certify power-loss safety or latency targets.

04 / EVALUATIONPython / Docker

AgentForge

Did the submission fail, or did the evaluator infrastructure fail?

Task contract → fresh trial → verifier → evidence
Show me a result
Six oracles pass and six broken baselines fail in real Docker, with assertions outside the candidate container.
The hard part
Keep verifier/infrastructure failures out of the candidate's scored failure denominator.
Evidence to inspect
253 tests include SQLite batch rollback after late credit/receipt failures. All 62 oracle checks pass; six broken baselines fail in real Docker. Reports reject comparisons across task revisions; historical v1 model scores stay separate.
Run it ↗Inspect the batch failure ↗
Tradeoff and next boundary

Independent RPC grading covers the six tasks. Public development tasks do not establish general model capability; broader hostile-code isolation and held-out comparisons remain open. Report authentication is a shared read key, not per-user authorization. Docker acceptance is recorded separately from the CPU walkthrough.
